# 什么是并发

并发的核心是处理共享资源，这也是为什么提到并发我们首先想到多线程并发，因为线程之间天然有大量共享的内容，并发的程度高，也更容易出现并发问题。

那进程之间是并发的吗？会有并发问题吗？一般没有，不仅是进程之间相对独立，且操作系统为我们兜底了，进程之间确实有共享资源比如文件、打印机，但操作系统已经把他们管理好了。或者说进程并发是操作系统层面考虑的事情而非应用程序，一个优秀的操作系统会让进程觉得自己独占了一切。

因此本文对并发的讨论以多线程为主，但大家要明白，无论线程还是进程都是一个逻辑上独立的任务、是顺序的指令。

# 并发问题

并发问题的根源，是因为多个线程要协作完成任务而产生相互制约的关系。

共享资源是最常见也是最重要的并发问题，但不是唯一。线程合作可以不共享资源，比如一个线程要等待另一线程的返回值。因为合作所以制约，制约主要分这两种：

- 同步（直接制约）：先完成A，才能完成B

- 互斥（间接制约）：使用共享资源的操作不能同时发生

但不论如何，并发的核心是处理共享资源，不必纠结有几个CPU核心。

# 同步问题

所谓同步问题其实就是并发问题，这是操作系统/计算机科学中一个著名的领域。确切来说，同步是解决并发的手段。因为对数据的并发访问，往往是因为指令顺序的不当导致数据不一致。而同步就是要纠正错误这些错误的顺序以确保协作的线程们有序推进。

# 互斥问题

所谓互斥问题其实也是并发问题，这是解决并发问题实现同步的一种行之有效的具体方案。我们之前说了：并发问题的核心是处理共享资源。所谓互斥就是：线程们不该同步操作共享资源，把对共享资源的并发的操作分开，分出个先后，操作顺序就对了，并发问题就解决了。

# 怎么解决并发问题

理解了上面的概念，解决并发问题的答案就显而易见了：

- 怎么决定这些操作的顺序（怎么实现同步）

- 怎么让一个线程操作时，另一个线程操作不了（怎么实现互斥）
