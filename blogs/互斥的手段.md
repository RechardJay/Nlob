# 硬件的支持

为何并发操作会有问题呢，因为一个线程的操作被打断了，线程恢复执行时，情况和之前已经不同了，本来正确的操作就不正确了。并发下的环境是不可靠的。

为了实现同步与互斥，我们需要一些可靠得、绝对值得信任的东西。

好在，现代的硬件提供了一种特殊的指令：原子指令。原子指令不可打断，其执行结果一定正确、符合预期的。这种指令就是compare_and_swap，CAS比较并交换。

```c
//从逻辑上看 CAS 就是给一个变量赋值，后返回旧值
int compare_and_swap(int *value,int expected,int new_value){
	int tmp = *value;
	if(*value == expected){
		*value = new_value;
	}
	return tmp;
}
// 但在CPU层面，这是一个原子操作。返回是否成功
CAS(V, E, N) = 原子执行 {
    if (V == E) {
        V = N;
        return true;
    } else {
        return false;
    }
}
```

注意：强调一下原子指令的结果一定正确、符合预期，而非操作一定成功。CAS操作会失败，这说明该变量被别人修改了。

# 实现 互斥

基于CAS，我们就可以实现 互斥 功能了：

```java
// 声明一个全局bool变量：lock，初始为false
bool lock = false;
// 仅当线程成功把lock 从 false 修改为 true时，才能进入临界区
while(!cas(&lock,0,1))

//临界区
//do...

lock = 0;
```

这便是 锁 的思想。 进入临界区之前用原子操作尝试修改lock，成功说明“抢到锁”，一个线程成功了其他线程便无法成功，因为bool不再符合false 的预期。当线程离开临界区时，再将lock置false“释放锁”，其他线程便可以强锁了。

前面说了，并发问题就两个：如何实现同步、如何实现互斥；我们已经解决一半了。
