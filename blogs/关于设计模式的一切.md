所有设计模式都在解决一件事——解耦。无论是应对复杂的业务迭代、冗余的代码重构，还是提升系统的可扩展性与可维护性，设计模式的核心价值从来不是炫技，而是通过**标准化的代码组织方式**，拆分模块依赖、隔离变化点，让代码从“牵一发而动全身”变成“各司其职、灵活扩展”。

# 设计模式的底层逻辑与分类

设计模式的祖宗是 面向对象设计的思想，在软件工程领域的GoF（四人组）在《设计模式：可复用面向对象软件的基础》中总结了23种经典设计模式，按照用途分为三大类，每一类都围绕“解耦”解决不同维度的问题：

- **创建型模式**：解耦“对象创建”与“对象使用”，隐藏创建细节，让调用方无需关心对象如何实例化、初始化，专注于业务逻辑。

- **结构型模式**：解耦“类/对象的组合关系”，通过灵活的结构拼装，让不同功能的模块协同工作，同时保持各自的独立性。

- **行为型模式**：解耦“对象间的通信与职责分配”，梳理对象交互流程，避免紧耦合的调用链，让行为可拆分、可复用。

# 封装

创建型模式的核心是**把“new对象”这件事封装起来**，解决直接new对象导致的依赖紧耦合、初始化逻辑冗余、单例冲突等问题。

## 1. 单例模式（Singleton）：全局唯一实例，避免资源浪费

避免多次创建重量级对象（如线程池、数据库连接池、配置类），解耦实例创建与全局调用。

**Java实现（双重校验锁，线程安全+高性能）**：

```java
public class Singleton {
    //  volatile禁止指令重排，保证多线程可见性
    private static volatile Singleton instance;

    // 私有构造器，禁止外部new对象
    private Singleton() {
        if (instance != null) {
            throw new RuntimeException("禁止通过反射破坏单例");
        }
    }

    // 双重校验锁获取实例
    public static Singleton getInstance() {
        // 第一次校验：避免每次加锁，提升性能
        if (instance == null) {
            synchronized (Singleton.class) {
                // 第二次校验：防止多线程同时进入第一层判断
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }

    // 业务方法
    public void printInfo() {
        System.out.println("全局唯一单例实例：" + this.hashCode());
    }
}

// 测试调用
public class SingletonTest {
    public static void main(String[] args) {
        Singleton s1 = Singleton.getInstance();
        Singleton s2 = Singleton.getInstance();
        // 输出true，证明是同一个实例
        System.out.println(s1 == s2);
    }
}
```

## 2. 工厂模式（Factory）：封装创建逻辑，统一对象产出

调用方无需知道产品创建细节，只需要通过工厂获取对象，解耦“产品创建”与“产品使用”。

多种同类产品（如不同品牌的手机、不同类型的消息推送器）、创建逻辑复杂的对象。

**Java实现（简单工厂+抽象工厂进阶）**：

```java
// 抽象产品：定义统一接口
interface Phone {
    void call();
}

// 具体产品：实现抽象接口
class HuaweiPhone implements Phone {
    @Override
    public void call() {
        System.out.println("华为手机拨号");
    }
}

class IPhone implements Phone {
    @Override
    public void call() {
        System.out.println("苹果手机拨号");
    }
}

// 简单工厂：统一创建对象
class PhoneFactory {
    public static Phone createPhone(String type) {
        if ("huawei".equals(type)) {
            return new HuaweiPhone();
        } else if ("iphone".equals(type)) {
            return new IPhone();
        } else {
            throw new IllegalArgumentException("不支持的手机类型");
        }
    }
}

// 测试调用
public class FactoryTest {
    public static void main(String[] args) {
        // 调用方只需要传类型，无需new具体对象
        Phone phone1 = PhoneFactory.createPhone("huawei");
        Phone phone2 = PhoneFactory.createPhone("iphone");
        phone1.call();
        phone2.call();
    }
}
```

# 依赖

结构型模式关注如何将现有类/对象组合成更大的结构，既保留模块独立性，又能实现功能叠加，避免重复编码。

## 1. 适配器模式（Adapter）：兼容不同接口，无缝对接

将不兼容的接口转换成调用方期望的接口，让原本无法协同工作的类一起运行，解耦“接口差异”与“调用逻辑”。

**Java实现（对象适配器）**：

```java
// 目标接口：调用方期望的标准接口
interface MediaPlayer {
    void play(String type, String fileName);
}

// 适配者：已有接口，与目标接口不兼容
interface AdvancedMediaPlayer {
    void playMp4(String fileName);
    void playVlc(String fileName);
}

class Mp4Player implements AdvancedMediaPlayer {
    @Override
    public void playMp4(String fileName) {
        System.out.println("播放MP4文件：" + fileName);
    }
    @Override
    public void playVlc(String fileName) {}
}

// 适配器：中转兼容，实现目标接口，持有适配者对象
class MediaAdapter implements MediaPlayer {
    private AdvancedMediaPlayer advancedPlayer;

    public MediaAdapter(String type) {
        if ("mp4".equals(type)) {
            advancedPlayer = new Mp4Player();
        }
    }

    @Override
    public void play(String type, String fileName) {
        if ("mp4".equals(type)) {
            advancedPlayer.playMp4(fileName);
        }
    }
}

// 具体播放器：使用适配器兼容格式
class AudioPlayer implements MediaPlayer {
    private MediaAdapter adapter;

    @Override
    public void play(String type, String fileName) {
        if ("mp3".equals(type)) {
            System.out.println("播放MP3文件：" + fileName);
        } else if ("mp4".equals(type)) {
            adapter = new MediaAdapter(type);
            adapter.play(type, fileName);
        }
    }
}

// 测试调用
public class AdapterTest {
    public static void main(String[] args) {
        MediaPlayer player = new AudioPlayer();
        player.play("mp3", "test.mp3");
        player.play("mp4", "test.mp4");
    }
}
```

## 2. 装饰器模式（Decorator）：动态增强功能，不修改原代码

在不改变原有类结构的前提下，动态给对象添加额外功能，解耦“核心功能”与“增强功能”。

**适用场景**：IO流增强、权限校验、日志埋点、功能叠加等场景。

**Java实现（咖啡加料场景）**：

```java
// 抽象组件：定义核心接口
interface Coffee {
    String getDesc();
    double getPrice();
}

// 具体组件：基础实现
class SimpleCoffee implements Coffee {
    @Override
    public String getDesc() {
        return "原味咖啡";
    }
    @Override
    public double getPrice() {
        return 10.0;
    }
}

// 装饰器抽象类：持有组件对象
abstract class CoffeeDecorator implements Coffee {
    protected Coffee coffee;
    public CoffeeDecorator(Coffee coffee) {
        this.coffee = coffee;
    }
}

// 具体装饰器：添加牛奶
class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) {
        super(coffee);
    }
    @Override
    public String getDesc() {
        return coffee.getDesc() + "+牛奶";
    }
    @Override
    public double getPrice() {
        return coffee.getPrice() + 2.0;
    }
}

// 测试调用
public class DecoratorTest {
    public static void main(String[] args) {
        // 动态叠加功能，无需修改原有咖啡类
        Coffee coffee = new SimpleCoffee();
        coffee = new MilkDecorator(coffee);
        System.out.println(coffee.getDesc() + "，价格：" + coffee.getPrice());
    }
}
```

# 调用

避免紧耦合的调用链，让系统流程更清晰、更易扩展。

## 1. 观察者模式（Observer）：一对多通知，自动触发更新

**解耦目标**：解耦“被观察者”与“观察者”，被观察者状态变化时，自动通知所有观察者，无需主动调用。

**适用场景**：消息推送、事件监听、订阅发布、状态同步等场景。

**Java实现（基于JDK原生Observer）**：

```java
import java.util.Observable;
import java.util.Observer;

// 被观察者：主题
class Subject extends Observable {
    private String message;

    public void setMessage(String message) {
        this.message = message;
        // 标记状态已改变
        setChanged();
        // 通知所有观察者
        notifyObservers(message);
    }
}

// 观察者：订阅者
class UserObserver implements Observer {
    private String name;

    public UserObserver(String name) {
        this.name = name;
    }

    @Override
    public void update(Observable o, Object arg) {
        System.out.println(name + "收到消息：" + arg);
    }
}

// 测试调用
public class ObserverTest {
    public static void main(String[] args) {
        Subject subject = new Subject();
        // 注册观察者
        subject.addObserver(new UserObserver("张三"));
        subject.addObserver(new UserObserver("李四"));
        // 被观察者状态变化，自动通知观察者
        subject.setMessage("设计模式博文更新啦！");
    }
}
```

## 2. 策略模式（Strategy）：切换算法逻辑，灵活替换

**解耦目标**：解耦“算法实现”与“算法调用”，将不同算法封装成独立策略，支持运行时动态切换。

**适用场景**：多种支付方式、不同排序算法、优惠策略计算等。

**Java实现（支付策略）**：

```java
// 抽象策略：定义算法接口
interface PayStrategy {
    void pay(double money);
}

// 具体策略：微信支付
class WechatPay implements PayStrategy {
    @Override
    public void pay(double money) {
        System.out.println("微信支付：" + money + "元");
    }
}

// 具体策略：支付宝支付
class AliPay implements PayStrategy {
    @Override
    public void pay(double money) {
        System.out.println("支付宝支付：" + money + "元");
    }
}

// 上下文：持有策略，对外提供调用入口
class PayContext {
    private PayStrategy strategy;

    // 动态切换策略
    public void setStrategy(PayStrategy strategy) {
        this.strategy = strategy;
    }

    public void executePay(double money) {
        if (strategy == null) {
            throw new RuntimeException("请选择支付方式");
        }
        strategy.pay(money);
    }
}

// 测试调用
public class StrategyTest {
    public static void main(String[] args) {
        PayContext context = new PayContext();
        // 切换支付宝支付
        context.setStrategy(new AliPay());
        context.executePay(99.0);
        // 切换微信支付
        context.setStrategy(new WechatPay());
        context.executePay(88.0);
    }
}
```
